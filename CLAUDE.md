# CLAUDE.md

## What this is

Linkbio by CodePath: a "link in bio" platform for Brazilian small businesses and agencies, a product of CodePath (https://codepath.dev.br). Production URL: `https://bio.codepath.dev.br` (customer pages at `/<slug>`); the company's own site lives at the apex domain in another project. Brand constants (`SITE_NAME`, `COMPANY_NAME`, `COMPANY_URL`, `SITE_HOST`) are in `src/lib/site.ts`. Product scope is in `docs/PRD.md`. Built with Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4 + PostgreSQL (via `pg`, raw SQL). The backend lives in this repo (`src/server/`); locally Postgres runs in Docker. All user-facing copy is Portuguese (pt-BR).

Follows the same conventions as the sibling site projects (`../site-moraex`, `../site_leticia_moraes`).

## Commands

- `npm run dev` — dev server (Turbopack)
- `npm run build` — production build
- `npm run start` — run the production build
- `npm run lint` — ESLint (flat config, `eslint-config-next`)
- `npm run db:up` — start local Postgres (docker-compose, port 5435)
- `npm run db:migrate` — apply pending `db/migrations/*.sql` (tracked in `schema_migrations`)
- `npm run db:seed` — dev-only demo account + page + 30 days of events (credentials at the top of `scripts/seed.mjs`)
- `npm test` — Vitest unit tests (`test/*.test.ts`); DB tests are skipped
- `npm run test:db` — also runs `test/*.db.test.ts` against the local Docker Postgres (via `TEST_DATABASE_URL`, never `.env.local`)

Env vars live in `.env.local` (see `.env.example`): `DATABASE_URL`, `APP_SECRET`, `NEXT_PUBLIC_SITE_URL`, optional `RESEND_API_KEY` + `MAIL_FROM` (password-reset e-mail; without them, in dev the e-mail is printed to the server terminal), and billing: `BILLING_ENABLED`, `ASAAS_API_URL`, `ASAAS_API_KEY` (starts with `$`: single-quote it in `.env` files), `ASAAS_WEBHOOK_TOKEN`, `CRON_SECRET`.

Tests live in `test/`; `vitest.config.mts` aliases `@` to `src` and stubs `server-only`.

## Architecture

- **`src/app/layout.tsx`** — fonts (Bricolage Grotesque + Manrope via `next/font/google`), global metadata/SEO, JSON-LD (`SoftwareApplication` + `WebSite`), `@vercel/analytics` and `@vercel/speed-insights`. `sitemap.ts`, `robots.ts`, `opengraph-image.tsx` (generated via `next/og`) and `icon.svg` are metadata files.
- **`src/app/page.tsx`** — marketing landing; only composes section components in order: `Nav`, `Hero`, `StatsBar`, `Recursos`, `ComoFunciona`, `Planos` (3 cards Grátis / Pro mensal / Pro anual, comparison table and FAQ, all derived from `src/lib/billing.ts`; with billing off it shows a "Lançamento" notice and every CTA says "Criar minha página"), `Cta`, `Footer`. Each section is a `<section id="...">` matching nav anchors (`#recursos`, `#como-funciona`, `#planos`, `#comecar`). Sections take no props and hold their own copy/data arrays.
- **App routes** — `[slug]` public page (ISR 60 s via `generateStaticParams` returning `[]`; dashboard actions call `revalidatePath`), `go/[id]` tracked redirect, `api/view` view tracking (posted by `ViewTracker`), `media/[id]` serves uploaded images from Postgres (immutable cache), `login` (email + password, `?modo=cadastro` for signup; `login/recuperar` requests a reset e-mail, `login/redefinir` sets the new password), `api/redefinir-senha` (reset link target: moves the token into the httpOnly `lb_reset` cookie and redirects, so it never stays in the URL), `dashboard` with tabs: Links (`page.tsx`), `aparencia` (client `AppearanceEditor` with live preview; its controls are `AppearanceFields`, shared with the playground), `resultados` (analytics), `plano` (plan/billing page; 404 when billing is off). All mutations are Server Actions in `dashboard/actions.ts` and `login/actions.ts`. `api/asaas/webhook` receives Asaas events; `api/cron/billing` is the daily Vercel cron (`vercel.json`, auth `Bearer $CRON_SECRET`). `demo` is a client-only playground (`Playground`) with the same Links/Aparência controls and live preview — no DB, nothing saved; sample images live in `public/demo/`.
- **`src/server/`** (all `server-only`) — `db.ts` (pg Pool + `query`/`queryOne`), `auth.ts` (scrypt passwords, sessions table keyed by sha256 of an httpOnly cookie token, `requireUser`, single-use 1 h password-reset tokens that also drop all sessions), `rate-limit.ts` (`auth_attempts` with hashed email/IP keys; rules in `RATE_RULES`; signin counts only failures), `mail.ts` (`sendMail` via Resend HTTP API, console fallback in dev), `media.ts` (image upload ≤ 2 MB, type sniffed from bytes, no SVG), `profiles.ts` (profile/link reads), `analytics.ts` (`trackEvent` with bot filter + dedupe + rate cap; `getStats`), `asaas.ts` (minimal Asaas v3 client via `fetch`: hosted checkout, cancel subscription, webhook envelope types), `billing.ts` (checkout/cancel, webhook ingest + idempotent event queue `billing_events` with claim/retry, invoice mirroring, grace expiry, `getPlan`). **There is no RLS: every query must filter by the owner's user id in code.**
- **`src/proxy.ts`** — only checks the session cookie exists for `/dashboard`; real validation happens in pages/actions via `requireUser`.
- **`src/lib/`** — `types.ts` (Profile/LinkItem/Appearance, button styles, fonts, theme presets), `validation.ts` (slug/URL/WhatsApp/color), `site.ts` (site URL/name from `NEXT_PUBLIC_SITE_URL`), `billing.ts` (pure billing rules: prices, free limits, `planState`, invoice status ranking, `applyPlanToLinks`).
- **Billing / paywall (Grátis + Pro)** — same design as the sibling Ambiento project: Asaas hosted checkout (recurring credit card, monthly R$ 9,90 or yearly R$ 70,80 = R$ 5,90/month; prices live only in `PRO_PRICES`), `externalReference = "linkbio:<userId>"` (events with another prefix belong to other products on the same Asaas account and are ignored). Only the webhook changes state; the checkout return (`?checkout=ok`) just polls (`AutoRefresh`). Plan state is **derived on read** by `planState` (active until `current_period_end` + 3 days tolerance; `canceled_at` = Pro until period end; `past_due` = Pro until `grace_ends_at`, 7 days; `courtesy_until` = manual free Pro). A new `SUBSCRIPTION_CREATED` cancels the previous live subscription at Asaas (cycle/card change never double-charges; checkouts while paid set `nextDueDate` to the paid-until date). Free limits are enforced server-side (`addLink` limit, layout forced/kept in `readLink`, 30/90-day stats) and at render (`toPageViewProps(profile, links, pro)` → first 5 links as buttons + "Feito com Linkbio"). With `BILLING_ENABLED` not `"true"`, everyone is Pro and billing routes 404.
- **Public page rendering** — `PageView` takes appearance as CSS variables (`--bio-bg`, `--bio-text`, `--btn-bg`, `--btn-text`) plus `bio-btn-*` / `bio-font-*` classes; the same component renders the public page, `/demo` and the dashboard `PhonePreview`. Each link has a `layout` (`button` with optional thumbnail, `featured` big image on top, `tile` square — consecutive tiles are grouped into a 2-column grid by `groupTiles`) and a `size` (`sm`/`md`/`lg`, `.bio-size-*`); edited via `LinkOptions` (uncontrolled radios inside each link form in the dashboard; controlled via `onChange` + `namePrefix` in the playground).
- **Analytics** — no IP or cookies stored; a daily visitor hash (`APP_SECRET` + day + profile + IP + UA) counts unique visitors and dedupes (view: 30 min, click: 30 s, max 120 events/visitor/hour). Source comes from in-app UA (Instagram/Facebook/TikTok…) or referrer host. Days are computed in `America/Sao_Paulo`. Chart colors are validated categorical slots `--series-1`/`--series-2`.
- **`src/components/RevealWrapper.tsx`** — polymorphic scroll-in `.reveal` wrapper (`IntersectionObserver`), combine with `.d1`–`.d4` delay classes. `Hero`/`StatsBar` skip it so above-the-fold content shows immediately.
- **Client components** — `Nav`, `RevealWrapper`, `ViewTracker`, `DashTabs`, `AppearanceEditor`, `TrafficChart`, `AutoRefresh`, `PasswordInput` (eye toggle), `SignupForm` (`useActionState` with `signUp`), `ImageInput` (shrinks photos in the browser via `src/lib/shrink-image.ts` so uploads never exceed the Server Action `bodySizeLimit`). `src/app/error.tsx` replaces Next's black error screen with a reload prompt.
- **Styling** — plain global CSS in `src/app/globals.css`: CSS custom properties on `:root` (`--ink`, `--paper`, `--lime`, `--whats`, …) plus BEM-ish classes (`.wrap`, `.btn-*`, `.h2`, per-section `.hero-*`, `.feat-*`, `.dash-*`, `.bio-*`). Tailwind v4 is imported but not used for styling — don't add Tailwind utilities ad hoc. Responsive rules are hand-written `@media` blocks at the end (900px, 600px). Public page appearance is driven by `--bio-*`/`--btn-*` variables set inline by `PageView`.
- **Security headers** — set centrally in `next.config.ts`.
- **Database** — `db/migrations/0001_init.sql`: `users`, `sessions`, `media`, `profiles` (incl. appearance columns), `links` (incl. `thumbnail_id`), `events`; `0002_link_layout_size.sql` adds `links.layout` and `links.size`; `0003_auth_security.sql` adds `auth_attempts` and `password_resets`; `0004_billing.sql` adds `subscriptions`, `invoices`, `billing_events`; `0008_user_details.sql` adds `users.first_name`/`last_name`/`instagram` (signup); `0009_whatsapp_style.sql` adds `profiles.whatsapp_style` (`green`/`theme`/`custom`) + `whatsapp_color`/`whatsapp_text_color`. Add schema changes as new numbered files, never edit applied ones.
